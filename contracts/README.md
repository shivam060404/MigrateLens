# Canonical transport contracts

These generated HTTP contracts belong to the optional enterprise control plane. The standalone `oss/` package reads local OpenAPI inputs and emits its own versioned proof manifest; it does not call this API to scan, patch or prove a fixture.

`json-schema/` and `openapi/control.json` are generated by `make schemas` from backend Pydantic models and the FastAPI app. Do not edit generated files.

OpenAPI includes the implemented control routes and their bearer security scheme. Control routes are available only when the local identity and runtime database are explicitly configured; the default process exposes health only. Frontend health and control request types are generated from the same models. Response records remain untyped until the persistent API is verified against PostgreSQL.

## Phase 1 evidence contracts

| Artifact | Canonical model |
|---|---|
| Individual validation evidence item | `Check` |
| Frozen acceptance plan | `MigrationPlan` |
| Proposed bounded patch metadata | `PatchProposal` |
| Validation matrix and result manifest | `ValidationEvidence` |
| Effective fixture policy | `Policy` |

New result manifests use version `2`: all outcomes bind source, policy, mapping, old/new contracts, implementation, runner, dossier and patch hashes (including an empty patch). Attempted repairs also bind the proposal and candidate. `dossier.json` contains the frozen plan/policy and proposal when applicable. Checksums cover every exported file.

Version `1` manifests remain readable as unsigned historical records. They cannot be re-exported through the current exporter because they lack the new dossier binding; rerun the case to create version `2` evidence. A hash proves content consistency, not authenticated provenance or approval.
